# Фронтенд «Запись на звонок»

Интерфейс реализован по контракту `api/openapi/openapi.yaml`. Код бэкенда не
читается: единственный источник знаний об API — сгенерированный из спецификации
клиент.

## Стек

| Что | Чем |
|---|---|
| Сборка | Vite 8 |
| Язык | TypeScript 5.9 |
| UI | React 19 + Mantine 9 |
| Роутинг | React Router 7 |
| Клиент API | `openapi-fetch` поверх типов из `openapi-typescript` |
| Даты | dayjs с плагинами `utc` и `timezone` |

TypeScript зафиксирован на 5.9: `openapi-typescript` пока не поддерживает TS 6,
который Vite ставит по умолчанию.

## Запуск

```bash
npm install
npm run gen:api      # типы из контракта -> src/api/schema.d.ts
npm run dev          # http://127.0.0.1:5173
```

Dev-сервер проксирует `/api` на адрес из `VITE_API_TARGET` (см. `.env.example`),
по умолчанию — `http://127.0.0.1:4010`. Сам код всегда ходит по относительному
пути `/api`, поэтому одинаково работает с моком, локальным бэкендом и за nginx.

### Разработка без бэкенда

```bash
npm run mock         # Prism поднимает мок по контракту на :4010
npm run dev          # в соседнем терминале
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run gen:api` | Генерирует `src/api/schema.d.ts` из `../api/openapi/openapi.yaml` |
| `npm run dev` | Dev-сервер с прокси на API |
| `npm run build` | Генерация типов, проверка типов, production-сборка |
| `npm run lint` | oxlint |
| `npm run mock` | Prism-мок по контракту на порту 4010 |

## Структура

```
src/
  api/
    schema.d.ts    сгенерирован из OpenAPI — руками не править
    types.ts       псевдонимы схем контракта
    client.ts      openapi-fetch + разбор ошибок в ApiError
    services.ts    по одной функции на каждую операцию контракта
  components/      переиспользуемые части экранов
  hooks/useApi.ts  загрузка данных: loading / error / reload
  lib/datetime.ts  форматирование времени в таймзоне владельца
  pages/           экраны
```

`schema.d.ts` перегенерируется на каждой сборке. После правки `main.tsp`
достаточно пересобрать спеку и запустить `npm run gen:api` — несоответствия
вылезут ошибками типов, а не в рантайме.

## Экраны

| Маршрут | Экран | Запросы |
|---|---|---|
| `/` | Лендинг | нет, статика |
| `/book` | Каталог типов событий | `GET /api/public/owner`, `GET /api/public/event-types` |
| `/book/:eventTypeId` | Календарь, слоты, форма гостя | `GET .../{id}`, `.../availability`, `.../slots?date=`, `POST /api/public/bookings` |
| `/bookings/:bookingId` | Подтверждение | `GET /api/public/bookings/{id}` |
| `/admin/event-types` | Типы встреч | `GET`/`POST`/`PATCH`/`DELETE /api/owner/event-types` |
| `/admin/bookings` | Предстоящие записи | `GET /api/owner/bookings`, `DELETE /api/owner/bookings/{id}` |

## Как соблюдаются инварианты контракта

Фронтенд ничего не вычисляет за сервер и не дублирует его правила:

- **Окно записи (14 дней)** — берётся из `windowStart` / `windowEnd`, границы
  календаря выставляются по ним. Своего отсчёта дат нет.
- **Доступность дня** — только по флагу `isBookable`; количество свободных
  слотов приходит в `freeSlots`.
- **Пересечение броней** — слоты со статусом `busy` показываются, но не
  кликабельны. Кто занял слот, интерфейс не знает и не показывает.
- **Длительность брони** — `end` не отправляется, его считает сервер.
- **Гонка за слот** — на `409 slot_taken` сетка дня и календарь
  перезапрашиваются, гостю предлагается выбрать другое время.
- **Время** — все моменты приходят в UTC и форматируются в таймзоне владельца
  из её профиля.
